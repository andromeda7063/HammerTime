### What the tensors mean

The configured v2 node vector has 20 ordered values (`hammertime_100/src/context_features.py:74-79,35-47`; `hammertime_100/configs/train_2023_fastf1_season_physical_v2.yaml:57-70`):

1. `Speed`
2. `Throttle`
3–7. `Compound_SOFT`, `Compound_MEDIUM`, `Compound_HARD`, `Compound_INTERMEDIATE`, `Compound_WET`
8. `TyreLife`
9. `MiniSector`
10. `SpeedRatioToTrainReference`
11. `SpeedDeltaToTrainReference`
12. `Brake`
13. `DRSActive`
14. `a_long`
15–16. `lap_sin`, `lap_cos`
17. `lap_phase`
18. `abs_curvature`
19. `lateral_accel_proxy`
20. `ReferenceAvailable`

Circuit ID and circuit length are not direct v2 numeric node inputs. Geometry uses position and speed from the current and two prior aligned grid frames (`hammertime_100/src/context_features.py:162-175,247-290`). The speed reference is train-only, but it is keyed to exact `CircuitId × MiniSector`. Since a race-held-out cohort also holds out circuits, such references are unavailable on unseen test circuits by design; v2 then uses ratio 1, delta 0, and support 0 (`hammertime_100/src/context_features.py:364-404`). The checksummed local v2 manifest lists 296,052 training frames and an empty `references` array. Its canonical `prepared_manifest_sha256` is `4aa94d93a82e5a34cad708a1ae1d9edafe81820538ff49f895e3eb7d02495ad5`; its `context_calibration_sha256` is `72bee81c409c48f79cc919c5a609b8c5ae799824756ab8be118255f1851f87e6`; and the recorded season-config file hash matches `0dc622e3fd8c9e39beadcecbda00594c71e9c6429f07b32ba321b4edae6e1c72`. The manifest records `git_head=fce9b4f75f0499511169d9cb9d1a65c2849ebe43`, the parent commit from before v2 was committed, and carries no implementation hashes. It proves the empty serialized summary but not which dirty source version produced it or what the 2.4 GB payload exposes. Verify payload/current-code compatibility before claiming references were populated or interpreting those node features.

Each snapshot is a PyG graph with `x:[N,20]`, `edge_index:[2,E]`, `edge_attr:[E,5]`, and node mask `[N]` (`graph.py:281-298`). In a batch of B windows, W=10, and N cohort drivers, the conceptual input is `[B,W,N,20]`; targets, masks, and model outputs are `[B,N]` (`model.py:267-324`). The 15-frame eligibility span is indices 0–14. The model sees indices 0–9 and predicts the label attached to index 14, 3.5 seconds after the first input frame and 1.25 seconds after the last input frame. The target’s timestamp is mini-sector entry time; its duration is measured through the next observed sector boundary (`target.py:72-94`). The output is a signed per-driver sector-duration residual, not total race time, force, or an iterative rollout. The final head is linear without a positivity clamp (`model.py:143-149,261-265`).

### Edges and causality limits

The five v2 edge features, in order, are RBF proximity, physical gap in metres, leader-minus-follower speed in m/s, position coverage, and a binary in-wake-corridor indicator (`hammertime_100/src/physical_graph.py:18-33`). Positions are sorted by circular distance modulo the configured circuit length, without lap number. Each follower receives an edge from its next physically observed car if the gap estimate is within the existing 2.0 s cutoff; the wake indicator is true at gap ≤35 m and ≤0.6 s (`hammertime_100/src/physical_graph.py:67-90,118-149`). The edge index is `[leader, follower]`, so PyG source-to-target message passing sends leader information to follower (`:140-141`). A follower has only one incoming physical neighbor; no reverse defensive relation or lateral proximity is represented. `PhysicalEdgeFeatureScaler` defines train-only normalization for physical distance and relative speed (`:161-220`). In the pre-GNNv2 standard dataset path, the scaler metadata was fitted but its transform was not applied; therefore physical_v2 edge attrs remained raw in the baseline model. The new typed-edge path applies that transform only when `model.typed_edge_values` is enabled, deriving active attrs from the preserved raw edge field with the unique training-input scaler. This does not change existing default configurations.

Installed `torch-geometric` 2.8.0.post1 source was inspected in the frozen environment. `GATv2Conv.edge_update` projects edge attributes into attention logits; `message` multiplies projected neighbor values by normalized attention. Thus edge features condition weights, not message values. A candidate edge-conditioned value transform is a substantive addition, not a description of current v2. Also, inactive cars remain as zero-feature nodes (`graph.py:185-210`). They are batched into each graph, and `GraphNorm` computes mean and variance over all nodes in a graph; no active-node mask is supplied (`model.py:267-310`). The reviewed edge builders create inter-car edges only for active nodes (`graph.py:219-222`; `physical_graph.py:133-141`), so direct messages from inactive cars are excluded; their inclusion can still shift GraphNorm statistics for active nodes.

There are two temporal caveats. First, linear interpolation at a grid time uses the samples on both sides of that time; an offline input frame can therefore depend on a later raw observation, up to the configured 1 s bracket limit (`preprocess.py:88-116`). This is data availability latency, not future target-label leakage. Second, target clean-air medians are computed from the complete session before the split (`target.py:104-140`). This is label calibration using potentially future held-out clean sectors, not an input feature used by the model. The current benchmark is retrospective session calibration, not a strict prospective evaluation with a reference known before the race. This is already recorded as open question #2.

The input schema omits driver identity, team identity, and weather/air or track temperature even though FastF1 weather is loaded. Speed, throttle, brake, DRS, tyre compound/age, and track context are included. An observed residual can therefore reflect pace, tyres, weather, strategy, incidents, and traffic together. The additive decomposition proposed below is a modeling aid; it cannot identify causal aerodynamic effects from these labels alone.

## Five research proposals

These are hypotheses for controlled experiments, not established gains. The existing target, metric definitions, source coverage, split, test holdout, acceptance flags, physics thresholds, and gates stay fixed. Keep the held-out races locked; select with validation only. Report paired per-race and per-lap diagnostics alongside existing pooled scores so large races do not conceal event-to-event variation. Do not change thresholds or use test results to select architecture.

### 1. Mask- and freshness-aware encoder with valid-node normalization

Add per-channel observation masks and elapsed time since the last observed source value for telemetry channels that can be absent; keep the existing active-target and coverage rules unchanged. The current preprocessing interpolates signals, uses zero values for unsupported DRS/acceleration/brake inputs, and collapses row validity into an active-node mask (`preprocess.py:88-144`; `context_features.py:221-230,407-452`). Test a validity-aware encoder and causal freshness inputs, plus normalization/propagation that excludes inactive nodes. In particular, compare GraphNorm with an active-node mask against per-node LayerNorm; do not let padded/inactive nodes change active-node statistics. Test the invariant that adding masked slots does not change valid-car predictions. This addresses a code-inspected representation issue; it is not a promised MAE gain. GRU-D motivates masks and time-since-observation features in clinical sequences, not race-data performance ([GRU-D](https://arxiv.org/abs/1606.01865)). GraphNorm is a graph-wise normalization method; its paper does not establish the masked-node defect identified here ([GraphNorm](https://proceedings.mlr.press/v139/cai21e.html)).

### 2. Typed sparse ahead and trailing-pressure messages

Preserve the current hard 2 s edge horizon in the first comparison. Extend the current immediate physical leader relation with at most two additional plausible cars ahead and a separately typed trailing-pressure relation. Use soft geometric, closing-speed, DRS/wake, and position-observability gates within that fixed candidate set. Distinguish absent relation from an observed relation with zero/neutral feature values. Test edge-conditioned message values alongside attention weighting, plus an own-car residual path. PyG 2.8.0.post1 source confirms the current GATv2 edge attributes affect attention logits, while messages are projected neighbor values multiplied by attention; they do not condition message values. Do not change the current physics gates. The aerodynamic literature supports checking axial and lateral wake effects, but uses older regulations and does not validate today’s numeric cutoffs ([SAE wake study](https://doi.org/10.4271/2017-01-1546)). Relational inference and message-passing work motivate typed interactions, not F1 validation ([NRI](https://arxiv.org/abs/1802.04687); [MPNN](https://proceedings.mlr.press/v70/gilmer17a.html)).

### 3. Interleave temporal updates and graph messages with past-only coarse memory

The current model applies two spatial graph layers at every observed frame, then applies temporal blocks per driver (`model.py:204-265`). Test interleaved temporal and relational blocks so each interaction step can use recent history. Add a separate past-only low-rate memory over roughly 10–30 seconds while retaining the current 4 Hz, 10-frame branch. This is a new context branch, not a longer eligibility span: preserve the current target anchor and window membership; mask additional context when unavailable. Reset/detach memory by race and driver, and update it only from timestamps at or before the last observed input frame (index 9). Do not read frames 10–14 or later-source telemetry without an explicit latency contract. Include the existing short-window model as matched-compute baseline. Graph WaveNet combines graph structure with dilated temporal modeling for traffic forecasts; TGN provides event-stream memory patterns, neither demonstrates F1 sector-residual gains ([Graph WaveNet](https://ijcai.org/proceedings/2019/264); [TGN](https://arxiv.org/abs/2006.10637)).

### 4. Additive pace/traffic head with nested regime modulation

Start with a small per-car state branch for slowly changing pace and stint context, plus a relational branch for short-horizon neighbor interactions. Sum them to predict the same signed `DeltaT_Sector`; retain the current target and SmoothL1 objective. Anchor the pace branch using authentic clean-air examples, but do not force the total prediction to zero in clean air: stint effects and calibration noise can remain. Require a zero interaction contribution only when the full modeled history is fully observed and contains no validated neighbors. Missing telemetry means interaction state is unknown. A dropped edge, a temporary graph gap, or a car just leaving a wake does not prove zero interaction; memory may persist. Pit stops may reset pace memory, but should not erase all other state by default. Branch components can exchange arbitrary offsets, so they are not causal estimates. Retain the existing clean-air total-prediction gate and report any conflict between total-label accuracy and that gate. As a nested ablation, use FiLM modulation from existing Brake, DRS, curvature, speed-reference support, and compound signals; only then consider a small corner/braking versus straight expert head if validation supports it. Keep predictions smooth and signed; do not prescribe physical sign constraints. Weather variables require separately reviewed source and coverage. Tire-state studies, FiLM, and TFT provide methodological analogies, not F1 residual validation ([state-space tire study](https://arxiv.org/abs/2512.00640); [FiLM](https://arxiv.org/abs/1709.07871); [TFT](https://arxiv.org/abs/1912.09363)).

### 5. Quantile forecasts and seed ensembles for uncertainty

Retain the current point SmoothL1 head and its acceptance criteria. Add noncrossing signed q10/q50/q90 outputs with an auxiliary pinball objective; compare 3–5 independent seeds and assess interval coverage by held-out race, driver, and stint. This proposal targets reliability and decision support, not an inherent MAE improvement. Compare uncertainty calibration under held-out circuits; deep ensembles do not guarantee calibration under this shift ([deep ensembles](https://arxiv.org/abs/1612.01474)). Begin after signal-bearing representation changes, so a weak point forecast does not acquire a misleadingly precise interval.

## Five additional research proposals

These proposals extend the first five; they are not measured improvements. Preserve the current target, eligible anchors, race split, input scaling, scoring, metric definitions, coverage rules, gates, and physics thresholds. Use the fixed validation partition for development and evaluate the held-out test partition only after the candidate and protocol are recorded. These changes would require new source or model work; none is implemented in this checkout.

### 6. Static circuit-map preview with car-to-track cross-attention

Provide the model a short, distance-indexed preview of the track segment the car is forecast to traverse: centerline curvature, heading change, and optionally width or corner annotations, encoded as fixed map tokens and attended to by the car state. The current context contains curvature derived from the present and two preceding telemetry samples, but no forward geometry (`hammertime_100/src/context_features.py:162-175,211-219,235-290`). The circuit registry has circuit ID, lap length, and slug but no centerline (`hammertime_100/run_2023_fastf1_season.py:46-73,156-180`); raw export and normalization do not persist or align track maps (`hammertime_100/src/ingest.py:70-101`; `hammertime_100/run_2023_fastf1_season.py:301-379`). This is therefore a data prerequisite, not a feature that can be switched on in existing tensors. Require authenticated pre-race geometry with defensible layout registration; FastF1 circuit markers alone are not a production-grade centerline because the official source describes them as manually created and not very accurate ([FastF1 circuit-info source](https://github.com/theOehrly/Fast-F1/blob/main/fastf1/mvapi/data.py)). Register the map to lap distance without using future telemetry from a held-out race. If a map is genuinely known before prediction time, using the held-out circuit's static geometry is compatible with the intended race-heldout evaluation; document the source, version, registration error, and cutoff. Compare a map-conditioned model with the current model and with scalar upcoming-curvature summaries under the same cohort. Vectorized-map and agent-context encoders motivate the representation, but their autonomous-driving results do not establish F1 sector-residual gains ([VectorNet](https://arxiv.org/abs/2005.04259)). A prior repository decision guide also mentions static waypoint attention, so this is new to the present five-item proposal set, not a wholly new repository idea.

### 7. Hierarchical team, driver, and as-of exogenous context

Add a compact context encoder that combines shrunk team and driver effects with weather known as of the last observed input frame. Team is carried from lap metadata and used in the clean-baseline teammate fallback (`hammertime_100/src/preprocess.py:191-200`; `hammertime_100/src/target.py:95-140,187-215`), but team and driver identities are not v2 node features (`hammertime_100/src/context_features.py:35-47,74-79`). FastF1 loads weather, but the raw-table exporter persists only laps and car telemetry and the normalization path does not align weather into model inputs (`hammertime_100/src/ingest.py:35-101`; `hammertime_100/run_2023_fastf1_season.py:301-379`). A weather branch therefore requires a provenance-aware as-of join, preserving missingness and update age; do not use weather readings after the last observed input. Use hierarchical shrinkage and an explicit unknown-identity fallback so a driver/team absent during training does not require a fabricated embedding. Do not infer latent fuel, tire temperature, or future strategy from identity. Compare identity-only, as-of-weather-only, and combined branches; report performance on unseen-driver/team slices when available without changing the established split or its gates. Static and historical covariates are a standard forecasting design pattern, not proof that these covariates are complete or useful here ([TFT](https://arxiv.org/abs/1912.09363); [DeepAR](https://arxiv.org/abs/1704.04110)). This proposal is data-availability dependent and has a material memorization risk because race-heldout partitions can share season identities.

### 8. Auxiliary decoder for the five intervening future telemetry frames

Retain the primary signed residual prediction at the existing anchor, and add auxiliary outputs for the authentic Speed, relative progress/gap, Throttle, Brake, and DRS observations in the five future frames currently reserved by the window (`hammertime_100/src/dataset.py:68-74,110-176`). At W=10 and K=5 the model sees frames 0–9 and the primary residual is associated with frame 14; frames 10–14 must be labels only for auxiliary losses, never decoder inputs or teacher-forced values at inference. Mask each channel by its observed validity and keep the current eligible-anchor rules. This is not dense residual supervision: the existing target builder attaches a single sector-duration residual at the sector-entry label time (`hammertime_100/src/target.py:26-101`). Auxiliary future telemetry is more frequent than those residual events, which could train the shared representation to preserve short-term dynamics while the primary SmoothL1 objective and scoring remain unchanged. Use a validation-selected, predeclared auxiliary-weight sweep and compare primary-only against each auxiliary target separately and together; report auxiliary error as diagnostic only. Multi-task representation learning motivates this experiment, but balancing objectives and forecasting results in other domains do not establish a gain on this target ([Kendall et al.](https://openaccess.thecvf.com/content_cvpr_2018/html/Kendall_Multi-Task_Learning_Using_CVPR_2018_paper.html); [TFT](https://arxiv.org/abs/1912.09363)).

### 9. Train-race-only masked-history pretraining

Before supervised fitting, pretrain the telemetry/graph encoder to reconstruct randomly masked *observed historical input channels* from the same train-race windows, then fine-tune on the unchanged residual objective. This is distinct from proposal 8: proposal 8 predicts later measurements as an auxiliary supervised task; this proposal reconstructs masked values within the past-only observed input. Use authentic telemetry and existing observation masks, and restrict all pretraining examples to the already assigned training races. Do not use validation or test races even without labels, and do not change the supervised split, anchors, or target. The prepared cohort has far more aligned rows and graph snapshots than residual labels, making representation reuse plausible, but those counts alone do not show that reconstruction features transfer to residual prediction. Compare supervised-only and pretrained variants with matched downstream training protocol and seeds, and include a no-pretraining control. Time-series contrastive learning and masked graph spatiotemporal pretraining provide analogies; their datasets and objectives are not F1 validation ([TS2Vec](https://arxiv.org/abs/2106.10466); [HGAurban](https://arxiv.org/abs/2410.10915)).

### 10. Cross-fitted full-target tabular/graph mixture

Train a strong tabular predictor of the same full residual target from causal own-car window summaries and available traffic aggregates, then combine its prediction with the graph model through a small, regularized gate that sees only prediction-time inputs. This differs from proposal 4: it does not assign pace and traffic semantic subcomponents; it blends two complete predictors of the same label. The repository already has XGBoost and single-car sequence baselines (`hammertime_100/src/baselines.py:30-64,67-181,184-207`), but the mixture must be evaluated against a tabular model trained for the identical v2 target, split, and input contract. Fit the gate only on race-grouped out-of-fold predictions generated within training races; use inner grouped folds for gate tuning. Do not train the gate on in-sample base-model predictions or use validation/test outcomes for cross-fitting. Compare tabular-only, graph-only, and gated blend on the fixed validation partition, then run existing test metrics and gates once after selection. A blend may help when the learners make different errors, but can add little if their errors are correlated. TabM motivates a modern tabular control; a proprietary-data tire-energy benchmark is not a direct comparison for this residual target ([TabM](https://proceedings.iclr.cc/paper_files/paper/2025/hash/c1ba41c694834aeef91ae161711d4939-Abstract-Conference.html); [Mercedes tire-energy study](https://arxiv.org/html/2501.04067v1)).

## Relative upside ranking across all ten proposals

The ordering below is a qualitative estimate of possible upside for the held-out residual MAE, not an observed gain, confidence interval, or promise. There are no percentage projections: no matching v2 held-out evaluation is available, and proposals can interact rather than add independently. It is not the implementation order. In particular, mask-aware normalization is a low-risk structural correction worth checking early even though its expected MAE upside is uncertain; reproducible cohort compatibility and the input-time causality contract are prerequisites for every experiment.

| Rank | ID | Proposal | Expected upside rationale and key uncertainty |
|---:|---|---|---|
| 1 | N6 | Static circuit-map preview | Supplies upcoming geometry absent from current features and directly relevant to future sector duration; depends on trusted map coverage and accurate distance registration. |
| 2 | O2 | Typed, edge-conditioned ahead/trailing graph | Adds omitted traffic context and makes edge attributes affect message content; only one immediate leader is currently represented. |
| 3 | O3 | Interleaved graph-temporal updates and coarse past memory | Adds longer-lived state and repeated interaction updates; longer context may be redundant or noisy. |
| 4 | O4 | Additive pace/traffic prediction with nested FiLM | Separates slow own-car context from fast interaction structure; branch contributions are not causally identifiable. |
| 5 | N8 | Future telemetry auxiliary decoder | Uses measured frames already present in eligible windows to shape dynamics; benefit depends on telemetry task transfer to sector residuals. |
| 6 | N10 | Cross-fitted tabular/graph mixture | Can exploit complementary errors from current graph and tabular predictors; gain may be small if predictions are highly correlated. |
| 7 | N7 | Hierarchical identities and as-of weather | Adds potentially useful context omitted from v2, but weather is not exported/aligned and identity effects risk memorization. |
| 8 | N9 | Train-only masked-history pretraining | Uses authentic unlabeled history but reconstruction may not transfer, especially with only 15 training races. |
| 9 | O1 | Mask/freshness-aware encoder and valid-node normalization | Fixes a concrete inactive-node GraphNorm sensitivity and exposes missingness age; size of effect on residual MAE is unknown. |
| 10 | O5 | Quantiles and seed ensembles | Most direct benefit is uncertainty/reliability, not point MAE; calibration under circuit shift is uncertain. |

The ordering is deliberately tentative. Map preview requires new data assets; a masked-node correction may be a better first engineering experiment despite its lower upside rank. Evaluate each proposal against the same source-compatible prepared cohort, with predeclared validation ablations, and preserve all existing gates and thresholds.

## Decision and verification

The highest-priority tests are proposals 1–3: #1 addresses inactive-node and missingness handling visible in the code; #2 broadens relational information and conditions message values on edge context; #3 adds longer past-only interaction context. Proposal #4 combines the own-car/traffic decomposition with a nested regime-modulation ablation. Proposal #5 is for uncertainty and reliability, not an MAE claim. A Mercedes proprietary-data tire-energy study found boosted trees stronger than the tested neural alternatives on its richer tire-energy target; retain strong tabular controls, but do not treat it as a direct comparison for HammerTime’s public mini-sector residual ([tire-energy benchmark](https://arxiv.org/html/2501.04067v1)).

Before fitting any candidate, save a protocol with candidate definitions, seeds, unchanged source sessions, split membership hashes, scaling, objective, compute budget, and stopping rules. Compare on the same frozen prepared cohort and validation set. Inspect the test set only after candidate selection is recorded; run the existing held-out metric and physics gates unchanged once for the selected candidate. Preserve unmeasurable physics outcomes as unmeasurable. No architecture or physics effect is established by this report.

## Implementation update — 2026-11-01

The new opt-in `hammertime_100/configs/train_2023_fastf1_season_gnnv2.yaml` implements a limited combination of proposals 1, 2, and 8. `model.mask_inactive_nodes` enables active-node-only graph normalization/propagation and a fixed history marker for inactive nodes; it is false by default, so legacy configurations keep their original forward path. The same candidate enables model-side typed edge-conditioned value messages over the physical-v2 edges, without changing the stored five-channel edge schema or adding new candidate relations. An auxiliary head predicts five future aligned-speed targets, while the primary signed sector-residual head remains the scored output.
