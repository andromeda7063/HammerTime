The message requires a previously observed Safety Car deployment; a stay-out notice without deployment remains an error. Unknown Safety Car messages still fail closed. Offline fixtures cover active-state retention, missing-deployment rejection, and continued rejection of an unreviewed enter-pits message; the 23-test OpenF1 adapter suite passes.

No explicit “SAFETY CAR IN THIS LAP” or later global green message appears. The cached feed replay now passes the stay-out notice but intentionally stops on the unresolved enter-pits message, so Zandvoort was not normalized or admitted to the training cohort. ## Graph-construction metadata-copy fix — 2026-10-31

Graph snapshot construction now iterates sorted timestamp groups directly and builds a no-copy local DataFrame view without pandas metadata attrs. This leaves the caller's frame untouched while preventing each `iterrows()` result from deep-copying the complete coverage/provenance attrs. A cProfile comparison on an authentic Monza slice (4,560 rows, 240 timestamps, 19 drivers) changed from 32.555 s with 20.1 million deepcopy calls to 1.088 s after the fix; cProfile and concurrent load affect wall time, so this is diagnostic evidence rather than an end-to-end benchmark. Five offline graph contract tests pass, including row-permutation output equivalence and caller-attrs preservation. An earlier generated partial used the slower builder and is preserved locally; the current expanded-cohort preparation uses the optimized builder.

## Batched temporal graph message passing — 2026-10-31

The temporal model now batches per-snapshot graph attention across a window while preserving each graph's node and edge structure. On one warmed B=128 CPU training step with authentic Monza training windows (W=10, N=20), measured reference forward/backward time was 2.850 s versus 0.464 s batched (6.15x); first warmup measured 10.13 s versus 0.441 s. Evaluation-output equivalence had maximum absolute difference below 4e-8. Dropout consumes random draws in a different order under batching, so training stochasticity changes; this throughput observation does not show predictive gain. The test partition was not iterated.

## Circuit-context and physical-graph comparison integration — 2026-10-31

Added an isolated comparison config and suite using existing frozen OpenF1 aligned/target tables. The prep CLI can verify and reuse these tables without downloading or normalizing them again; it derives train-input frame keys from the unchanged legacy split, fits circuit/mini-sector speed references only on active training input rows, and asserts train/validation/test membership plus train/validation target and mask hashes are unchanged after feature construction. The context schema appends ten support-aware fields to the existing nine, including sampled trajectory curvature/lateral-acceleration proxies and a train-only speed reference. Physical-circuit edges use circular `Distance % lap_length_m` adjacency and retain the legacy race-progress edges alongside them; edge-distance and relative-speed scaling fits unique train-input edges only.

The validation-only `circuit_physics_v1` suite declares five matched views: legacy inputs/graph, context inputs/legacy graph, context/physical scalar, context/physical four-channel edges, and context/self-loop-only. All use the same gated-dilated temporal model, masked MAE training, existing validation-MAE checkpoint selection, targets, split, physics thresholds, metrics, and gates. The suite screens seed 42, chooses at most one eligible non-control view by its declared validation-only rule, and confirms that view plus legacy control on seeds 43/44. It also records train-mean, XGBoost, and LSTM validation baselines, per-circuit/sector MAE/RMSE/bias, prediction/target variance, runtime, parameter count, scaler/schema metadata, and unchanged target/mask hashes. No test loader is passed and no test score is produced by this workflow. The trajectory features are geometric proxies and physical nearest-observed adjacency is uncertain under sparse/noisy position telemetry; the comparison does not guarantee improved R². No comparison training or results are claimed in this entry.

## Complete-epoch training resume — 2026-11-01

`train_model` now accepts an optional `resume_from` last-epoch checkpoint while retaining the existing positional call and validation-MAE best-checkpoint behavior. Each completed epoch atomically writes a separate last checkpoint with model/Adam state, epoch, best score/epoch, early-stopping wait, full history, and Python/NumPy/torch/CUDA plus loader-generator RNG states. Resume is rejected when config, train/validation sample and graph inputs, scaler state, model shape, or run identity does not match. If a crash occurs after `best.pt` is replaced but before the matching last checkpoint is committed, resume restores the best state embedded in the prior last checkpoint and replays that epoch. A tiny offline interruption fixture matched the uninterrupted optimizer/RNG trajectory and checked config/data/scaler rejection; this is contract coverage, not authentic training evidence.
